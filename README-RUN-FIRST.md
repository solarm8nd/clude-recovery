# clude recovered agent

This package is a terminal-first recovery build around the uploaded source tree.

## What it does now

- starts cleanly from the terminal with `npm start`
- works **without any local model** for:
  - project analysis
  - file inspection
  - search
  - shell commands
  - recovery checks for bridge, chrome, and computer-use
- can use a local OpenAI-compatible model later if you configure one

## What was added

- `agent.js`: runnable terminal agent
- `recovery/`: recovery modules for shell, file, bridge, Chrome, computer-use, and offline analysis
- `scripts/analyze.js`: project-wide analysis script
- `package.json`, `tsconfig.json`, `.env.example`, `start-clude.ps1`, `clude.cmd`

## Important limitation

The original large source tree under `src/` is still incomplete as an upstream codebase. This recovery layer does **not** claim that the original source is now fully build-complete. It gives you a usable terminal agent around that tree and adds a repeatable analysis workflow.

## Run from scratch

### Windows PowerShell

```powershell
cd "C:\path\to\clude_recovered_agent"
node -v
npm start
```

Or:

```powershell
.\start-clude.ps1
```

## Offline mode examples

These work even if no local model is configured:

```text
حلل المشروع
اعمل انلسيز للبروجكت ده
اعمل خطة اصلاح
```

Or use a slash command:

```text
/analyze
```

That command also writes:

- `PROJECT-ANALYSIS.md`
- `project-analysis.json`

## Optional local model

You can either set environment variables before launch:

```powershell
$env:LOCAL_LLM_BASE_URL="http://127.0.0.1:11434/v1"
$env:LOCAL_LLM_MODEL="your-local-model"
$env:LOCAL_LLM_API_KEY=""
npm start
```

Or create a `.env` file in the project root:

```env
LOCAL_LLM_BASE_URL=http://127.0.0.1:11434/v1
LOCAL_LLM_MODEL=your-local-model
LOCAL_LLM_API_KEY=
```

## Feature notes

- Chrome and Computer Use are optional integrations.
- They are started through a local Claude-compatible binary if one exists.
- Set `CLAUDE_CLI_PATH` only if you know the real path to a working binary.
- Bridge is controlled through `.clude-recovery.json`.


## Source compatibility mode

This project now includes a second path that tries to boot the original `src/` tree more directly.

### Install dependencies
```bash
npm install
```

### Recovery agent
```bash
npm start
```

### Source smoke test
```bash
npm run source:smoke
```

### Source doctor
```bash
npm run source:doctor
```

Files generated by the doctor:
- `SOURCE-DOCTOR.md`
- `source-doctor.json`

### Notes
- `bun:bundle` imports were replaced with a local compatibility shim at `src/shims/bun-bundle.ts`.
- Several unavailable/private integrations are shipped as local file-based stub packages under `vendor-stubs/` so the source tree can boot further instead of failing immediately on missing packages.
- This does **not** guarantee that every original feature works. It is meant to push the original source tree farther toward booting while preserving the recovery agent as the fallback entrypoint.
